# PMCO project guidance

PMCO is a Tauri 2 physical music catalogue and audio player, shipping on Windows first. It catalogues CD, vinyl, cassette, SACD, DVD, Blu-ray and Other media, including mixed-media sets; native drive extraction remains CD-only. This is the single project instruction file for coding assistants. Read `STATUS.md` for the current handoff; consult source and focused tests for implementation details.

## Working rules

- Implement the requested scope; preserve existing data and behavior. Keep updates concise, inspect relevant code and run meaningful checks. Avoid duplicate testing or unnecessary parallel agents.
- Push, build, publish or change versions only when requested. An authorized Windows build normally includes committing/pushing to `Yuritnos/CDC` main, manually running `build-windows.yml`, and downloading `PMCO-windows`. Verify both installers in staging before replacing `installers/nsis/` and `installers/msi/`. No tags/releases unless asked.
- Never put privileged Supabase keys, tokens or passwords in the app, source control or logs. Only the publishable key belongs in the app. Let the owner enter credentials; do not send their email to unrelated services. Ask before database drops or renames.
- Tests use isolated fixtures/mocked services, never the owner's collection/account. Keep this file stable and short. Update `STATUS.md` at milestones with results, pending work and limitations; replace stale entries rather than append a transcript.

## Code map and checks

- `src/index.html`: all HTML, CSS and plain JavaScript; no framework/bundler. `I18N` keys must exist in en/ja/zh; use `t()` and `data-i18n*`. Use theme tokens; support system/light/dark, keyboard access and reduced motion. Release work-title resize observations when headings are removed.
- `Store`/backend owns persistence; `Cloud` owns Supabase sync. Preserve Tauri, HTTP `/api/data` preview and conditional `window.claude` artifact paths.
- `src-tauri/src/lib.rs`: atomic saves, backups, cover/audio files, bounded folder imports and native commands. Collection/backups/covers live under app data; audio defaults there and may use a computer-local chosen folder. Retain the previous-save backup and newest 14 daily backups. Validate paths; cleanup must preserve referenced files and Undo/draft semantics.
- `src-tauri/src/cd_drive.rs`: Windows CD-drive track counts/durations, bounded CDDA reads, bundled FLAC/WAV and cancellable staged jobs; no metadata recognition. Preserve physical track mapping and draft ownership/recovery; never use real drives or the owner's library in automated tests. `scripts/prepare-flac.ps1` pins the encoder/source archives.
- `src-tauri/tauri.conf.json`: product name `PMCO`, identifier `com.cdc.collection`; keep `dragDropEnabled: false` so Windows permits internal dragging. Restrict asset access to the library's audio/covers folders. Preserve legacy installer keys, MSI upgrade code and `cdc.exe` when changing branding.
- `.github/workflows/build-windows.yml`: Windows NSIS/MSI artifacts and generated `src/build.js`. Keep versions equal in `package.json`, `src-tauri/Cargo.toml` and Tauri config. Installers/build metadata are ignored.
- `supabase/README.md`, `schema.sql` and `migrations/`: account setup and server rules. A local migration file or UI placeholder does not prove hosted settings changed.
- Run `node tests/<relevant-test>.cjs`; broader coverage is `tests/collection-integration.cjs`. Focused suites cover lookup, performer roles/stress, work inheritance/form/tooltips, sections/rendering, audio drafts and unsaved forms. `npm run dev` starts Tauri; `npm run build` builds installers only when authorized. Bundled Node fallback: `%USERPROFILE%/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe`.

## Data and product invariants

- Document: `{cds, meta:{albums,playlists,order,settings}, sync:{metaAt,deleted,account}}`. Internally `albums` means Favorites (CD groups); playlists hold `{cdId,file}` tracks. Keep them separate. Preserve older optional fields, migrations and hidden `cd.set` through edits/import/export/sync.
- Missing `medium` means legacy CD. The editor offers CD/Vinyl/Cassette/SACD/DVD/Blu-ray/Other, with free text for Other; preserve saved USB/SD/custom values. All media folds six child views, combining DVD/Blu-ray while retaining their exact editor values/badges; Other has no submenu. Keep Medium name inputs mounted during redraws so typing, selection and IME composition retain focus. Mixed sets open complete profiles from each matching view. Medium is inside Filter only in All music; Collection uses the medium sidebar. Label is not a filter. Statistics groups physical items by the same six media categories. Filtering never changes the queue or playlists.
- Only Title is required for a standalone CD; sets share this title and need valid item counts. Each disc's composer/type/performers are independent defaults; blank work fields inherit via `workMetadata`. Manual work performers replace defaults; imported `performersMode: "additional"` adds extras. Preserve ordered `{role,name}` pairs; display each person once with combined roles, using linked role/name rows in both standalone/set profiles. Role pickers use buttons/checkbox panels, not native details/toggle loops. Alt+drag or Alt+Up/Down reorders whole performer rows within their disc/work draft.
- Works have optional composer/type/performers/duration and `tracks`. Undivided works consume one audio/numbering slot without an automatic work number; tracks continue across works. Cassette/DVD/Blu-ray/Other undivided works support printed `work.position`, with lossless transfer to/from the first/last track. Vinyl uses editable A/B sides (`cd.sides`, `work.side`) with numbering restarted per side and stable global audio slots; side switching alone is clean. Full-width side tabs each own edit/delete controls; rename fields appear on demand. With zero tracks, duration belongs beside the work and audio gets a virtual slot; otherwise durations belong to tracks. Catalogue and matrix/runout are separate; preserve legacy combined values. Hide condition/capacity fields without deleting saved data. Type/hub/audio technology and vinyl/cassette details allow free text plus suggestions; both year fields accept free text. Clear hub is 胶圈 (accept legacy 透明圈). Label/issuer and recording/release years remain distinct; Notes ends Disc details.
- Disc information starts open; Works starts open for saved/imported content and folded when empty; Audio starts folded. Preserve manual fold states across disc tabs; folding alone is not a change. Profile durations sit at the far right; an info icon precedes a single-line duration, or shares its right edge on the first line when the title wraps (duration on the last line). Popups align to the icon and open above/below the whole heading using the disc-info placement rules. Changed-form closing offers Save/Discard/Keep editing. Audio draft discard removes only newly copied files.
- Cards show Title plus at most six chosen fields; optional Favorites tags do not count (`-albums` hides them). Type uses a localized FORM/value row on home-page cards and profiles. CDs follow changing settings defaults until explicitly overridden. Card width is continuous, fixed per card rather than stretched.
- Sort: Custom order (default), Recently added, Composer surname A–Z, Title A–Z. Shelf reordering requires Alt+drag or Alt+arrows in Custom order with no search/filter; medium views move complete releases in the shared All media order while hidden releases retain relative order. Queue/playlist reordering preserves the playing entry and grouped-disc boundaries. Keep short opening/closing and unfold/fold animations, reduced-motion support, and avoid replaying unfold animations on redraws.
- Shelves always group set members into albums; counts show albums/items (standalone counts as one album) and Statistics includes Albums. Choose standalone/set before medium; standalone uses one format. Sets have one shared Title; each item tab edits its name (`set.subtitle`) and exact medium. On Save unify component/release titles, retaining former distinct titles as item names; never migrate on load. Standalone hides disc tabs/tools. Sets use one editable `set.cover`; preserve legacy disc artwork without exposing per-disc uploads. All media/Favorites cards open profiles with Edit/Favorites/Delete release; All music owns play/enqueue/link/playlist actions. Hide Add a CD in All music; use Add music in playlists. Adjacent queue/playlist tracks from one CD group into a foldable disc with disc/track removal. Queue medium tips belong on top-level release/work rows, never unfolded track rows. Preserve Undo and delay destructive audio cleanup until it expires.
- Audio is copied locally, never uploaded; only metadata syncs. File/folder imports share draft ownership and rollback. Folder scans skip links/junctions and the audio library, with 5,000-file/50,000-entry/16-level bounds. Missing files on another computer remain identifiable. Covers are content-addressed files locally, embedded pictures for sync/export. Editing preserves untouched audio/covers; cropping is shared with avatars.
- Discogs lookup matches barcode/catalogue/matrix; chosen results replace lookup-owned values, preserve user covers and save only on confirmation. Cover fallback: Rust Discogs download, then MusicBrainz/Cover Art Archive. Explicit work/index/track credit scopes override headline-artist inference; never spread a scoped performer across the set. Promote only metadata shared by all works to defaults; keep differences per work. Collapse a lone repeated-title track into work duration only; preserve distinct movements and multi-track works. Keep the public 028944443028 credit fixture regression. `LOOKUP_SOURCES` remains the extension point; do not silently migrate saved CDs.
- Local collection works offline. Sync uses newer CD timestamps and deletion markers; first sync must offer merge/remove-local/sign-out when local-only data exists. Keep unique User ID and separate nonunique nickname (20 characters), plus cropped avatar with C default. User IDs use 6–20 ASCII letters, numbers or underscores; existing shorter IDs survive unchanged. User ID changes have a 30-day/720-hour cooldown in client/server; retain timestamps and show only a generic monthly notice. Deployment status belongs in `STATUS.md`.
